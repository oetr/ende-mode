#+TITLE: Problems Summary
#+STARTUP: overview

- Near-term work should focus on credential safety, permissive resource circuit breakers, predictable review controls, structured-edit recovery, asynchronous correctness, and accurate status reporting.
- Features that are not connected yet, larger review UX changes, documentation work, and future agent privacy design are tracked separately in =DEFER.org=.
- The existing =C-c e= binding and summary badge placement are accepted for now and require no immediate change.

* DONE Bind Codex OAuth tokens to official origins
The OpenCode access token can currently be attached to an overridden Codex profile URL, and the refresh token can be sent to a customized issuer.
Generation and model discovery credentials must only be sent to the exact =https://chatgpt.com:443= origin.
Refresh credentials must only be sent to the exact =https://auth.openai.com:443= origin.
Official Codex endpoints should be internal constants or validated immediately before adding credentials rather than silently ignoring unsafe overrides.
See =deslop-codex.el:30=, =deslop-codex.el:45=, =deslop-codex.el:50=, =deslop-codex.el:223=, =deslop-codex.el:396=, =deslop-codex.el:783=, and =deslop-provider.el:138=.

* DONE Add permissive network circuit breakers
Configured endpoints are trusted, so normal local inference must not fail because it is slow or produces a large response.
Total request duration and provider output-token limits should remain unlimited by default.
The existing response idle timeout should remain the primary timeout for stalled requests.
Very high byte limits should prevent accidental runaway memory or disk use without acting as ordinary product limits.
Suggested ceilings are 256 MiB per response, 16 MiB per SSE event, 128 million parsed output characters, 1 MiB of headers, 1 MiB of error preview, 16 MiB for discovery, 1 MiB for OAuth refresh, and 16 MiB of stderr.
See =deslop-core.el:23-95=, =deslop-provider.el:67-93=, =deslop-curl.el:177-193=, and =deslop-curl.el:257-265=.

* DONE Bound structured edit expansion efficiently
One structured edit using ="all": true= can expand into an edit for every matching anchor even though the number of raw edits is capped.
Replacement conflict detection compares every pair and can perform quadratic work on a large buffer.
Use a generous normalized-edit circuit breaker rather than a restrictive product limit.
Sort edit intervals and detect conflicts in a linear pass after sorting.
See =deslop-edit.el:70-78=, =deslop-edit.el:93-137=, and =deslop-edit.el:168-208=.

* DONE Retry failed structured edits with model feedback
Structured operations currently apply valid edits once, retain successful edits, and settle without giving the model a chance to repair failed edits.
After the first pass, send the updated document, original task, failed edits, and exact diagnostics in a follow-up request.
The follow-up must request only the remaining work and must tell the model not to repeat successful edits.
Add a configurable repair-attempt count with one attempt as the proposed default.
Keep the job active across repair rounds and report first-pass applications, repaired edits, final failures, and attempts used.
See =deslop-operations.el:366-426= and =deslop-operations.el:452-506=.

* DONE Make RET confirm selector choices
The provider and model selector binds =RET= to approving every pending review in the source buffer rather than confirming the current selection.
Backspace similarly rejects every pending review, making familiar chooser keys perform broad and potentially destructive actions.
Bind =RET= to =deslop-selector-confirm=.
Bind =C-c C-c= to approve all source reviews and =C-c C-k= to reject all source reviews for consistency with review overlays.
Remove the mass-review actions from Backspace and deletion keys.
See =deslop-selector.el:115-117=, =deslop-selector.el:238-272=, and =deslop-selector.el:340-342=.

* DONE Stop review overlays from hijacking editing keys
Review overlays bind =RET= to approval and =DEL=, Backspace, and =C-d= to rejection.
Trying to insert a newline or delete one character can therefore approve or replace an entire generated region unexpectedly.
Preserve normal editing keys and bind =C-c C-c= to approval and =C-c C-k= to rejection.
See =deslop-review.el:30-38= and =deslop-review.el:264-323=.

* DONE Remove obsolete buffer-freezing machinery
The target abstraction still contains fields, functions, and mutation-hook behavior for an abandoned design that made buffers read-only while jobs ran.
The current operation specifications do not request freezing, so this machinery is dead complexity.
Remove the freeze capability, target fields, freeze and thaw functions, and freeze-specific hook branch.
See =deslop-operation.el:33-52=, =deslop-target.el:31-36=, =deslop-target.el:249-271=, and =deslop-operations.el:546-590=.

* DONE Reject read-only write targets before dispatch and application
Structured write-anywhere and insert-anywhere operations dynamically bind =buffer-read-only= to nil while applying edits.
This defeats the writability check in =deslop--mutate-target= and allows model output to alter a deliberately read-only buffer.
Check writability before dispatch to avoid paying for an unusable completion.
Check writability again immediately before applying output because the user can make the buffer read-only while the request runs.
See =deslop-operations.el:180-213=, =deslop-operations.el:252-263=, =deslop-operations.el:389-409=, and =deslop-operations.el:476-495=.

* DONE Fix atomic OAuth credential replacement
The OAuth credential writer passes the intended directory as the initial-content argument to =make-temp-file=.
The temporary file is consequently created in the normal temporary directory and =rename-file= can fail across filesystems.
The temporary file is necessary because writing it completely and renaming it preserves either the old or new credential file if writing fails.
Create the temporary file beside the credential file and retain restrictive file permissions.
See =deslop-codex.el:157-188=.

* DONE Coalesce concurrent OAuth refreshes
Every request that observes an expired token can launch an independent refresh and write to the shared OpenCode credential file.
Refresh-token rotation and out-of-order completion can cause requests to invalidate one another or overwrite newer credentials.
Maintain one in-flight refresh with waiting callbacks and verify the stored credential version before replacement.
See =deslop-codex.el:60-61=, =deslop-codex.el:201-320=, and =deslop-codex.el:825-852=.

* DONE Validate Codex HTTP responses before success
The Codex transport settles successfully as soon as it parses a =response.completed= or =response.done= event.
It can therefore accept output before validating the final HTTP status, content type, and complete SSE termination state.
Record completion events but defer success until process finalization performs the same checks as the generic transport.
See =deslop-codex.el:623-670= and =deslop-codex.el:745-757=.

* DONE Cancel all jobs when their source buffer is killed
An active job currently fails when its target buffer is killed, while queued jobs for that buffer remain queued until they are later skipped.
Killing a source buffer should immediately cancel every active and queued job targeting that buffer as a predictable panic button.
This behavior applies only to buffer-backed jobs and does not replace safe handling for future path-based tools.
See =deslop-target.el:292-325= and =deslop-queue.el:296-326=.

* DONE Prevent stale selector probe callbacks
Reopening the singleton selector resets its buffer-local state before the previous model probe is explicitly cancelled.
A stale asynchronous callback can consequently update a newly reused selector buffer, and external buffer killing does not cancel the probe.
Cancel before mode reinitialization, add a generation token, and install a buffer-local kill hook.
See =deslop-selector.el:136-162=, =deslop-selector.el:254-266=, and =deslop-selector.el:355-371=.

* DONE Report partial structured-edit outcomes concretely
Structured operations mark a job completed whenever at least one edit applies even if several other edits fail.
Individual failures are sent through repeated echo-area messages that overwrite one another and are easy to miss.
Show an aggregate message such as =deslop: applied 9 of 10 edits; 2 repaired; 1 skipped=.
Store structured counts for requested edits, first-pass applications, repaired edits, skipped edits, repair attempts, and final failures.
Render the durable history status as =COMPLETED WITH WARNINGS= when any edit remains skipped.
See =deslop-operations.el:400-424=, =deslop-operations.el:487-504=, and =deslop-history.el=.

* DONE Share transport session and finalization machinery
The generic and Codex transports duplicate callback safety, settlement, cleanup, resource accounting, partial results, and process lifecycle code.
The implementations have already diverged in HTTP validation, status reporting, and output-token handling.
Extract a shared asynchronous session and finalization layer while leaving wire-format parsing in transport adapters.
See =deslop-llm.el:38-114=, =deslop-codex.el:489-606=, and =deslop-codex.el:768-779=.

* DONE Remove the hidden operations load-order dependency
=deslop-operations.el= calls =deslop-trim-trailing= from =deslop-commands.el= without requiring that feature.
Directly requiring the operations feature can therefore fail with a =void-function= error depending on load order.
Move this generic string helper into =deslop-core.el= or declare the architectural dependency explicitly.
See =deslop-commands.el:21-23= and =deslop-operations.el:14-25=.

* DONE Sanitize and truncate selector labels
Provider and remotely discovered model names are inserted directly into a fixed-width selector layout.
The =%-24s= format specifies a minimum rather than maximum width, so long or multiline labels can distort or visually spoof rows.
Apply the existing single-line sanitizer and truncate values according to display width.
See =deslop-selector.el:90-118=, =deslop-selector.el:126-134=, and =deslop-provider.el:316-347=.

* DONE Keep parallel queue policy stable
A parallel job enqueued while its provider is at capacity is permanently rewritten as a sequential job.
Equivalent jobs can therefore receive different scheduling semantics based only on transient load, which reduces throughput and overrides user intent.
Keep the profile snapshot unchanged and let the admission check defer the parallel job until capacity is available.
See =deslop-queue.el:201-231= and =deslop-test.el:1310-1338=.

* DONE Use equal provider identities in FIFO tracking
The queue compares provider identity with =equal= in one place but uses =memq= for the set of providers already considered.
Two separately constructed profiles can contain equal URL strings that are not the same Lisp object.
The later job can then bypass an older blocked job for the same endpoint despite the intended per-provider FIFO rule.
Use =member=, =cl-member= with =equal=, or a canonical provider key.
See =deslop-queue.el:135-146= and =deslop-queue.el:184-199=.

* DONE Apply the output-token limit to Codex requests
=deslop-max-output-tokens= is included in generic chat-completions requests but omitted from the Codex Responses request body.
Users who explicitly configure a common output limit can therefore receive unexpectedly long or costly Codex generations.
Map the option to the Responses API =max_output_tokens= field while keeping the default unlimited.
See =deslop-core.el:50-56= and =deslop-codex.el:768-779=.

* DONE Delete settled change sets from the registry
The package-wide internal hash table maps change-set identifiers to proposals so they can be applied or rejected after a tool call returns.
Applied and rejected entries currently remain in the table indefinitely even though history is the appropriate place for settled results.
Delete entries immediately after successful application or rejection while retaining pending entries until explicitly settled.
Do not add arbitrary count or age limits at this stage.
See =deslop-tools.el:463-471=, =deslop-tools.el:635-673=.

* DONE Show active job and review counts in the lighter
The minor-mode lighter currently shows only active and queued jobs targeting the current buffer.
When reviews exist, render =deslop[ACTIVE|REVIEWS]=, such as =deslop[1|2]= or =deslop[0|2]=.
When no reviews exist, preserve the compact =deslop[ACTIVE]= form.
Refresh the lighter whenever a review is created, approved, rejected, or removed in bulk.
See =deslop.el:43-64= and =deslop-review.el:206-350=.

* DONE Correct reversed provider navigation keys
The selector binds =p= to the next provider and =n= to the previous provider while model navigation follows the conventional opposite direction.
This inconsistency makes navigation needlessly surprising to Emacs users.
Bind =n= to next and =p= to previous and update the displayed key hints.
See =deslop-selector.el:101-103= and =deslop-selector.el:326-331=.

* TODO Clarify remaining cross-module internal APIs
Functions named with feature-private double hyphens are routinely called from sibling modules as if they were supported interfaces.
This makes module boundaries misleading and makes apparently local refactoring capable of breaking unrelated features.
Perform this cleanup only after the behavioral, transport, review, and tool architecture has stabilized to avoid unnecessary renaming churn.
The shared JSON accessors, provider model URL helper, and project root normalizer are now documented public APIs.
Promote the remaining intentionally shared functions to documented APIs or place them in explicit shared internal modules.
Remaining examples include =deslop-curl--*= and the SSE/parser helpers in =deslop-protocol.el=.
