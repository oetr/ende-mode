#+STARTUP: overview

*ONLY HUMANS ARE ALLOWED TO CHANGE THIS DOCUMENT; AIs and LLMs --- STAY THE FUCK AWAY.*

These issues are intentionally deferred while the core interaction model is developed.
They should not block current work, but their rationale is retained so they can be reconsidered with the relevant feature.

* TODO Design deletion reviews
An empty replacement currently creates a zero-width review overlay that cannot show the removed text clearly.
A complete deletion-review design should display what was removed and allow the user to approve or restore it.
This is larger than an overlay edge-case fix and is deferred until the review workflow is expanded.
See =ende-tools.el:484-510=, =ende-tools.el:563-588=, and =ende-review.el:186-198=.

* TODO Add fallback labels for tool-generated reviews
Ordinary request reviews know the configured endpoint host and model even when the endpoint does not report metadata.
Tool-generated reviews currently pass nil client and model values because tools are not connected to a provider job.
When tools are integrated, use an honest fallback such as =[ende tool review]= rather than invented endpoint metadata.
See =ende-review.el:165-171=, =ende-review.el:217-237=, and =ende-tools.el:583-588=.

* TODO Make review faces theme-aware
The current subtle review background is readable for the primary development theme but may not adapt well to other themes or terminals.
A future implementation should inherit a subtle background from a semantic face such as =diff-added= while preserving font-lock foreground colors.
Underlines should not be used because they produced poor visual results in the current design.
The badge should eventually inherit from a semantic face instead of relying on fixed yellow.
See =ende-core.el:104-109=, =ende-review.el:131-161=, =ende-review.el:233-237=, and =ende-ui.el:21-24=.

* TODO Design provider-scoped agent history and tool permissions
Memory-only history in a single-user Emacs session is useful and is not treated as a standalone security problem.
Future agents must not automatically share history between local and remote providers or across unrelated projects.
Agent memory should be scoped by provider, project, and session, with explicit policy controlling what history is supplied to a model.
Tool access should use explicit project and buffer capabilities so enabling agents does not expose every live buffer by default.
See =ende-history.el:22-40= and =ende-tools.el=.

* TODO Add change-set ownership and access policy
=ende-tools--change-sets= is already package-internal by Emacs naming convention, but Emacs Lisp cannot enforce true variable privacy within the process.
A buffer-local table is unsuitable because change sets may target closed files and may be applied from another buffer.
When agent sessions are implemented, pending change sets should be owned by a project or session and accessed through capability-checking APIs.
Immediate deletion of settled entries remains a current task in =PROBLEMS-SUMMARY.org=.
See =ende-tools.el:463-471=.

* TODO Reconsider the default minor-mode binding
The package intentionally keeps =C-c e= as the practical default for now even though =C-c LETTER= is conventionally reserved for users.
There is no universally collision-free minor-mode key because major modes already use much of the reserved =C-c C-LETTER= space.
Reconsider an unbound default or a customizable prefix after the interaction model is stable.
See =ende.el:35-41=.

* TODO Make closed-file tool writes atomic
Closed-file change sets currently validate a digest and then overwrite the original path directly with =write-region=.
A concurrent modification or interrupted write can be clobbered or leave the source file partially written.
The risk is deferred because project tools are not connected to model transports yet.
Before tools become accessible, revalidate file identity and use a mode-preserving same-directory temporary file followed by atomic rename.
See =ende-tools.el:601-641=.

* TODO Decide how project tools enter the default facade
=ende-tools.el= implements a substantial project-agent and disk-edit subsystem that is loaded by =ende.el= but is not wired into the current model transport path.
Tool integration and whether tools should remain in the default facade will be decided when agent tool calling is developed.
See =ende.el:27= and =ende-tools.el=.

* TODO Add explicit review navigation mode
Review navigation is deferred even though the lighter will gain a pending-review count now.
A future =ende-start-review= command may enable a focused review navigation state with =M-n= for next, =M-p= for previous, and =C-q= to quit.
The design must continue allowing users to edit generated text normally and must avoid overlay-local interception of ordinary editing keys.
A tabulated list of reviews is not needed for the initial implementation.
See =ende-review.el:249-350=.

* TODO Complete package metadata and documentation
README, license, changelog, installation instructions, privacy documentation, curl dependency documentation, and broader autoload coverage are deferred until the product workflow is usable.
This work should be completed before public distribution rather than blocking current interaction development.
See =ende.el:1-14=, =ende.el:76-100=, =vision.org:7-24=, and =Roadmap.org:1=.

* TODO Add continuous integration and split tests
The large =ende-test.el= file mixes transport, queue, UI, review, project-tool, security, and integration tests.
Splitting tests by subsystem and adding byte-compilation, ERT, checkdoc, and package-lint automation are deferred as product-polish work.
This should be revisited before supporting multiple Emacs versions or publishing the package.

* TODO Revisit summary badge placement if it becomes disruptive
The current summary overlay begins before the separator inserted ahead of a later summary, so a later badge can appear immediately after previous LLM output.
This behavior is accepted for now because repeated unreviewed summaries are not a prioritized workflow.
No change is required unless real summary usage shows that the placement is confusing or destructive.
See =ende-summary.el:44-56=.
